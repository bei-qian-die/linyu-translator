04四个必须知道的实现细节

这几条都是实测踩出来的，不写下来下次改样式一定会再踩一遍。

坑 01

backdrop-filter 会破坏 fixed 定位

桌面端顶栏有 backdrop-filter: blur(8px)，而底部导航正是它的子元素。 毛玻璃会给元素自身创建 containing block，于是 position: fixed; bottom: 10px 变成「相对顶栏底部 10px」—— 导航直接粘在屏幕上方。
解法：移动端顶栏去掉毛玻璃、改不透明底色，毛玻璃留给底部导航自己用。

坑 02

iOS 输入框必须 16px

桌面端搜索框是 13px，手机上一聚焦，Safari 会把整页放大到 16px 等效宽度，而且失焦后不会缩回去。 所有 input / select / textarea 在移动端统一抬到 16px，改字号比加 maximum-scale 更正确 —— 后者会顺手禁掉用户的双指缩放。

坑 03

平板和触屏本子会被 UA 骗

iPadOS 13+ 的 UA 伪装成 Macintosh，纯看 UA 会判成桌面；反过来，触屏笔记本窗口拖窄又会被判成手机。 判定顺序是：明确桌面 UA 先否决 → 再看手机 UA → 最后用「粗指针 + 最小边 ≤ 820px」兜底。 另外支持 ?ui=mobile / ?ui=desktop 手动覆盖，存在 localStorage 里。

坑 04

刘海屏与小白条

顶栏 padding-top: calc(6px + env(safe-area-inset-top))， 底部导航 bottom: calc(10px + env(safe-area-inset-bottom))， 内容区底部再额外留 88px —— 否则 iPhone 的横条会压住最后一条词条。 页面高度用 100dvh 而不是 100vh，避免地址栏收起时底部被裁掉。

05桌面端：一个像素都没动

所有移动端规则都挂在 body.mobile-app 前缀下。 桌面浏览器不会挂这个类，web/mobile.css 里 400 多条规则一条都不命中。下面是同一份代码在桌面 UA 下的渲染结果：

linyu-translator.app.workbuddy.host

自动化断言里专门做了这组对照：桌面 UA 下 body.mobile-app 必须不存在、导航必须不是 fixed、翻译页必须仍是双栏、表格行必须仍是 table-row。
