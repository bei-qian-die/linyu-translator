# 2026-11-06 · 1.38.0 音乐板块扩展（三轨 A/B/C）

## 需求

音乐板块从「静态音源库」扩成「能用的音乐板块」：接入网易云 / QQ 音乐官方音源页，音源 62 → 150+；构建脚本去硬编码；四端加收藏 / 最近浏览 / 排序 / 每日一条 / 随机一条 / 分享。用户确认：**不新增梗品类，只扩野花香与 Gulp 两条梗的搞怪版本**，总量按「音源 ≥150」执行。

## 采集口径

- 网易云：`music.163.com/song?id=<数字id>`；评论数当 `usage_count`；搜索接口取候选后逐条开歌曲页核 `<title>` 含歌名。
- QQ 音乐：`y.qq.com/n/ryqq/songDetail/<id>`；公开接口不返回播放量 → `usage_count = null`，不估算；开页跟随 302 后核 `<title>`。
- B 站：`search.bilibili.com` + `api.bilibili.com/x/web-interface/view?bvid=` 判 `code === 0`；音源条目链接是引用该音源的作品页，`music_id = null`、`platform_id = BV`。
- 抖音：登录池剩余 17 组全是「@xx创作的原声」/ 电商号 / 模板音乐，音源名不含梗关键词 → 本轮新增 0。
- 每条入库条目都开过页；候选 → 去重 → 合规 → 作者上限 → 配示例，最终 62+88=150 条音源 / 225 条二创。

## 去重与合规

- 三路基线：slug 唯一、每平台 `platform_id` / `music_id` 唯一、示例作品 id 全批唯一；同作者跨平台合计 ≤2。
- 黑名单叠加：擦边 / 性暗示 / 裸 / 诱 etc；带货与电商号；教程 / 前端构建工具（`gulpfile` 会误伤 Gulp 梗）；AI Cover；影视搬运；合集 / 串烧。
- **Gulp 只认梗音源本身**：网易云里大量同名器乐 / 乐队歌 / 游戏 BGM，名字撞 `Gulp` 但与梗无关 → 要求 `name` 含 gulp 且 `author+name` 含 `cupcakke|jiafei|memesvices|杯糕`，最终只留 3 条官方音源，其余用 B 站真实二创条目补。

## 轨道 B：平台注册表

- 新文件 `scripts/music-platforms.js`（CJS 供 build 与 test 共用）：平台表 `{key, label, shortLabel, musicUrlRe, exampleUrlRe, idField, idRequired, musicIdPolicy, usageUnit, usageLabel}` + `TAG_META`。
- `build-music.mjs`：按平台校验链接形态、id 必填性（required / null / copy）、id 与 URL 尾段一致、平台内唯一、示例 URL 反推平台；`buildGroups()` 自动生成「全部」与每梗分组，`TAG_META` 只定 key / 顺序，desc 用条目数 + 高频玩法统计。
- `test/music.test.js`：正则、唯一性、平台筛选器全部跟随注册表；保留既有断言。
- **新增平台 = 加一条配置 + 数据里写 `source`，脚本零改动**；新增梗 = 数据集里写新 tag（可选在 TAG_META 里定顺序）。

## 轨道 C：用户态存储选型

- 桌面 / 安卓：SQLite 新表 `music_favs(id PK, platform, created_at)` / `music_seen(id PK, seen_at)`，走现有 SCHEMA；IPC `ly:music:favs|toggleFav|seen|markSeen` + preload 同名方法。
- Web：`linyu.music.favs` / `linyu.music.seen`（localStorage），`window.__linyuMusicStore` 让库未就绪也能读。
- 小程序：`miniprogram/services/musicFav.js`，内存缓存 + `wx.setStorageSync`，页面不直接碰 Storage。
- 排序：热度按平台内 max 归一化；每日一条 = FNV-1a(`本地日期|slug`) 取最高分；分享小程序 `onShareAppMessage`，其余复制链接 + 推荐语。
- 小程序 tabBar 不动（仍 5 项），收藏 / 最近浏览做成音乐页内次级 chip。

## 新坑

1. **浏览记录回顶**：`ON CONFLICT DO UPDATE` 不换 rowid，同一毫秒连续浏览时 `ORDER BY seen_at DESC, rowid DESC` 会把老行留在原位 → 改成 `DELETE + INSERT`。
2. **示例池被官方条目先吃掉**：先给网易云 / QQ 配示例会把高质量 B 站二创消耗掉，导致 B 站音源条目凑不够 → 先**预留** B 站音源条目，再分配示例。
3. **作者上限要提前占位**：挑选阶段只检查不递增，跨平台会把同一作者选到 5 条 → 挑选时就 `takeAuthor`。
4. **同名梗源污染**：网易云「Gulp」大量同名器乐 / 乐队 / 游戏 BGM，必须按作者 + 梗关键词二次过滤。
5. 网易云核验有少量误杀（HTML 实体 `&amp;` 未解码），232 条候选够用，没重跑。
6. PowerShell 5 不支持 `&&`，分号或分开跑；复杂中文 `node -e` 转义容易失败 → 写 `.mjs` 脚本。

## 遗留

- QQ 音乐无播放量；抖音采集池需换关键词重新登录采集。
- 官方音源条目的示例来自同梗 B 站二创，`music_used` 按数据集约定 = 音源名，不宣称同一录音版本。
- 网易云 / QQ 候选池里仍有少量同名同曲不同版本，靠作者上限压住，后续可加「同曲多版本」人工复核。
