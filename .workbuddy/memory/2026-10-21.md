## 淋语翻译器（Electron + Capacitor）项目体检

对仓库做了一次全量优化点排查，输出优先级矩阵（收益 × 成本四象限）。核心结论：

- **立即动手（低成本高收益）**
  - `src/renderer/img` 71 张人物图全是 PNG，总计 8.4MB（单张最大 557KB）；人物列表 `v-for="h in filteredHeroes"` 无分页、无 `loading="lazy"`，首屏一次性解码 → 转 WebP + 懒加载 + 缩略图。
  - `src/core/db.js:1052 addHistory()` 调了两次 `run()`，每次 `run()` 内部都 `persist()` = 整库 `db.export()` + 同步写文件 → 一次翻译两遍全库落盘。应走 `batch()` 合并 + 只在超限时裁剪 + 延迟落盘。
  - `src/core/tokenizer.js` 每次 `translateText` 都重建 dict Set 与 maxLen，匹配是 O(n×maxLen) 的 `slice().join('')` → 按词库版本缓存编译结果。
  - 仓库根目录散落 16 个 `corpus*.txt`（~3MB）+ `c5~c7.err/log`、`mined*.txt`、`attest.txt`、`lore.bak`、`seen.json`；`scripts/legacy/` 20+ 一次性脚本；`www/`（build-mobile 产物，11MB / 97 文件）已入库。

- **排期重构（高成本高收益）**
  - 全项目 0 行 TS，`package.json` 里 vue3 但求职方向是 Vue3+TS → 先 `core/` 加 JSDoc + `@ts-check` 渐进。
  - `src/renderer` 是 `createApp({...})` 单体：app.js 1291 行 + index.html 683 行 + style.css 2082 行，无 SFC、无构建工具（直接 `<script src="vendor/vue.global.prod.js">`）→ 迁 Vite + 组件拆分，面试门面价值最高。
  - 桌面 `src/main/main.js`（521 行）与移动 `src/mobile/api.js`（649 行）是两套平行业务 API 实现，IPC 契约改动需双写 → 抽公共 service 层，两端只做传输适配。

- **顺手做**：CSP 里 `script-src` 开了 `unsafe-eval`/`unsafe-inline`、`img-src https:` 任意域，可收紧；Electron 33 / Capacitor 6 可升。

- **暂缓**：虚拟滚动（数据量 535 词 / 73 人，收益有限）。

1. **`.gitignore` 其实已经覆盖了大部分临时文件**（`c*.log/err`、`mined*`、`lore.bak`、`seen.json`、`attest.txt`、`audit.txt` 都已忽略）。所以"清理根目录"这一项不是删文件，而是：16 个 `corpus*.txt` 移到 `corpus/`（**不能删**，check.js 靠它做语料溯源）、`hero4/5_evidence.json` 等挪进 `evidence/`、`scripts/legacy/` 归档。
