# 2026-11-05 · 1.36.0 四端「跳至第 N 页」

## 需求

用户想要：需要翻页的地方能直接输入页码跳过去，不用一页一页点；顶部和底部各加一个跳转入口；键盘敲数字也能翻页；四端（PC / Web / 安卓 / 小程序）全部更新；打包后旧版本删掉、新版本放原目录；推 GitHub + Gitee。

## 实现

### 渲染层（src/renderer，桌面 / Web / 安卓共用）

- `usePaged` 扩出 `draft{top,bottom}` + `jumpTo(which)` + 内部 `parsePage()`：
  - 两个输入框各自存草稿，避免「上面输入 12、下面跟着显示 12」
  - 全角数字 / 「第10页」/ 空格都能解析，越界由 `go()` 夹到首末页
- 四个列表（词库/句式/词卡/名言）在 search 下方插 `.pg-jump` 顶栏、在 `.pager` 里插 `.pg-jump.inline` 底栏（index.html 各 2 处，共 8 处）
- 键盘直跳：复用 onMounted 里已有的 document keydown 分支 —— 焦点不在 input/textarea/select/contenteditable 且当前视图 pages>1 时，数字键累积到 `kbJump.digits`，右下角浮层显示，Enter 落页（`kbJumpGo`）、Esc 取消、2.2s 自动清空
- 样式：`.pg-jump/.pg-input/.kb-jump` 加在 style.css 的 `.pg-info` 之后；`appearance: textfield` 去掉数字箭头；`body[data-mobile]` 下输入框 74px、隐藏浮层；`@media (max-width:568px)` 让 `.pager` 折行

### 小程序

- 新增 `miniprogram/utils/pager.js`：`countPages / clampPage / parsePageInput / pageSlice` 四个纯函数
- 词库页（主包）与 browse 页（pkg-hero 分包）：`loadMore` 累积模型 → `renderPage(page)` 整页替换；`goPage / onJumpInput / doJump / stepPage`；`applyFilter(reset)` 在 setData 回调里 `renderPage(reset?1:this.data.page)`
- wxml：列表上方插 `.pg-bar`（第 N/M 页 + 跳页框），列表下方 `.pg-bar.pg-bar-foot`（上一页 / 页码 / 下一页 + 第二个跳页框），替换掉 `<list-foot>`
- 样式统一写在 `miniprogram/app.wxss`（两页共用）
- 历史页仍是「加载更多」，没动

### 测试

- `test/weapp.test.js`：B3 改为断言整页替换（30 条恒定、第 2 页首条 = 全量第 31 条、越界夹范围、jumpVal 跟随）；新增 B15 覆盖 pager 纯函数 + 分包页跳页 + 换 tab 回第 1 页
- `scripts/_verify-jump.cjs`（新）：Edge headless + CDP 打开本地 www-web，断言 4 个列表各 2 个跳页框、顶框输 10 回车落第 10 页、裸敲 2+3 回车落第 23 页、底框输 5 落第 5 页，截图 promo/_jump-check(.mobile).png

## 踩坑

- Gitee 附件配额是**仓库级 1GB**，不是单文件 100MB 那么简单；超了会报「文件大小已超出仓库附件配额：1 GB」，但小文件（24MB 的 .003）还能挤进去 → 补传前必须先删旧附件
- `git add release/ www/ www-web/` 会被 .gitignore 拦下并整条命令失败（exit 1），得用 `git add -u` 更新已跟踪文件 + `git add -f` 单独加新文件
- 写验收脚本时 `.tab` 选择器不存在，导航按钮其实是 `nav.tabs button`；另外后台 `python -m http.server` 用 `&` 起会被收掉，必须用 run_in_background
