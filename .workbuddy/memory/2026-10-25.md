## 1.16.1 修桌面端"卡死"（模板未渲染）
- 现象：PC 端窗口全是裸 {{ }} 模板（截图 10-25 05:34）。根因是 1.12.4 起的两个叠加回归，1.13.0 就已存在（日志显示用户 10-18 在 1.12.3/1.13.0 间反复切换后退回 1.12.3），1.15/1.16 沿用坏配置必现。
- 根因①：index.html 是"www 自洽布局"相对引用（vendor/ seed-data.js core/ mobile/），桌面端从没生成过 → vendor/vue.global.prod.js 404 → app.js 里 `const {createApp}=Vue` ReferenceError → Vue 永不挂载。asar 里 renderer 只有 app.js/index.html/style.css/img。
- 根因②：10-22 的"CSP 收紧"把 script-src 'unsafe-eval' 换成 wasm-unsafe-eval，但 Vue 完整版用 DOM 内模板、挂载需 new Function → 即使资源齐了 mount 也被 CSP 拒（EvalError）。安卓 1.16.0 APK 同样中招。
- 附带雷③：lore-extra3..12 都在顶层 const cards/quotes/heroes，普通 script 共享全局词法作用域第二个起 SyntaxError；安卓没事是 build-mobile.mjs 有 wrapDirInIIFE，桌面从来没有。
- 附带雷④：mobile/entry.js 在桌面 WebView 会执行本地 sql.js 初始化并覆盖 preload 的 IPC window.api。
- 修复：scripts/prepare-desktop.mjs（npm start/dist 前置，铺 vendor/core/mobile/seed-data 进 src/renderer/ + IIFE 包装，生成物进 .gitignore）；IIFE 提取为 scripts/lib/wrap-iife.mjs 与 build-mobile 共用；index.html CSP 加回 unsafe-eval；entry.js 顶部加 preload 守卫（window.api 存在且非 stub 非 thenable → return）。
- 新增 scripts/e2e-render.js：CDP 驱动真实 Electron 的渲染层冒烟测试（Vue 挂载/无裸模板/api=preload/listWords、listHeroes 非空）。注意 IPC handler 被 main.js wrap() 包成 {ok,data}，断言要拆包。本机 shell 有 ELECTRON_RUN_AS_NODE=1 + NODE_OPTIONS（WorkBuddy 宿主），spawn electron.exe 前必须清掉，否则退化成纯 Node 跑 main.js。
- 校验：e2e-render OK（词库 1144/人物 164）；npm run check unattested=0；npm test 全绿。cap sync 很慢（约 5 分钟）且上次 APK 在 sync 完成前就打出来导致 APK 缺 index.html —— 打 APK 前确认 assets/public/index.html 存在。
- 产物：release/淋语翻译器 Setup 1.16.1.exe（88MB, 7ed5ef85…）、淋语翻译器 1.16.1.exe（80MB, 53147c75…）、linyu-translator-1.16.1-debug.apk（18MB, versionCode 11610）。1.16.0 Setup 已删；便携版 1.16.0.exe 被运行中进程占用删不掉，关掉卡死窗口后手动删。
