### 关键技术发现（后续别踩）

1. **真 .ts 迁移在当前架构下不可行**（P9 只做了一半）。TS 7 移除了 `module: "none"`，
   而 CommonJS 产物在 WebView 里会 `ReferenceError: exports is not defined`（= 1.12.4 白屏故障复发）；
   改用 export 又会因多个「全局脚本」共享作用域报 TS2451（tokenizer/translator 都声明 buildTokenizer）。
   → 真 .ts 应在引入 Vite/bundler 之后做。当前落地的是 `// @ts-check` + JSDoc + `jsconfig.json`
   + `types/globals.d.ts`（声明 linyuScrypt / window.* 等双环境全局），`npm run typecheck` 已进 CI。
2. **auth.js 的 scrypt 既有 bug**：只认全局 `linyuScrypt`，而 `scrypt.js` 的 Node 分支从不挂这个全局，
   桌面端开发者登录实际会 ReferenceError（crud-check 那条失败就是它）。已改为 Node 侧
   `require('../mobile/scrypt')`，crud-check 失败项 4 → 3。
3. **translator 缓存初始化 bug**：`ruleCache` 初始 `compiled: null` 且 sig 为 `''`，
   当 rules 为空（签名正好是 ''）时跳过编译 → `for...of null` 崩。已改 sig 初始为 null 哨兵。
4. `lore.js` 「斯琴低娃老师」`links` 键重复定义（后覆盖前），已保留含两条链接的那份。
5. 本机 `scripts/e2e-dev.js` 跑不通（连不上 Electron 调试端口，基线即失败），
   **无法做桌面真机自动化冒烟**——任何 UI 层改动都需要人工验证。
6. `check.js` 的 CRUD 契约（3 项）与语料溯源（unattested 339）是**基线即失败**，与本次改动无关
   （已在 HEAD 干净副本上比对确认）。
