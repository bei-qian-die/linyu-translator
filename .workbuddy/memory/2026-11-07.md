## 背景

工作区在 11-06 由其它会话推进到 1.38.0（音乐板块 62 → 150 条、收藏 / 最近浏览 / 排序 / 每日一条），但线上仍停在 1.36.0。用户要求「部署 linyu-server 或 www-web、覆盖同一 appId、链接不变」，并做线上核验。

## 关键判断：部署目录选 www-web

- `.wbapp_Sd4kigAmHhvYV7chB2LAcw.genie` 里 `localDir` 指向 `www-web`，appId = `wbapp_Sd4kigAmHhvYV7chB2LAcw`。
- 站点发布工具「发布哪个应用由 `directory` 决定」，显式传 `appId` 也不能把发布挪到别处。传 `linyu-server` 会另起应用、链接会变；且 `linyu-server/index.js` 是一体 Node 服务（静态站 + `/polish` 智谱中转），注释里写明「一个工作区只有一个已发布应用槽位，独立代理会把静态站顶掉」。
- 结论：**只有 `www-web` 能满足「覆盖同一 appId + 链接不变」**。`diff -rq www-web linyu-server/public` 无差异，两者都是 1.38.0 完整构建，所以不损失内容（只是不带 `/polish` 同源代理）。
- 参数：`language=static`、`entryHtml=index.html`、`domainPrefix=linyu-translator`、`userAskedToPublish=true`、`appId=wbapp_...`。发布后 `sandboxId=97cd9d39330b41dbb4411defa1c627bf` 与上次一致，链接保持 https://linyu-translator.app.workbuddy.host/?sharecode=KYSNKQPHS7。

## 新坑：GitHub git 端点被代理挡住

- 推 GitHub 时 `schannel: server closed abruptly (missing close_notify)`，换 `http.sslBackend=openssl` 变 `CONNECT tunnel failed 502`，去掉代理直连超时；但 `api.github.com` 走同一代理返回 200，说明是代理对 `github.com` 的 HTTP/2 路由问题，不是凭据问题（不要去 reconnect connector）。
- **解法：`git -c http.version=HTTP/1.1 -c http.sslBackend=schannel push github HEAD:master` 一次成功。**
- 顺带查出 GitHub `master` 当时还停在 1.36.0 的 `50db4c0` —— 1.37 / 1.38 的三次提交此前没推上去；本次一笔把 4 个提交全补齐，两端现在都是 `e7ec5dc`。

## 手机端网页「看不到新增音乐」= 缓存事故（本轮修复）

- 现象：桌面/全新手机会话都是 150 张音乐卡，用户手机却是旧数据。`scripts/_verify-mobile-1380.cjs` 用 390x844 + Android UA 模拟，确认 150 卡、网易云/QQ 音乐筛选按钮都在、零报错 → **线上代码没问题，是手机浏览器缓存**。
- 根因：`index.html` 里所有资源 URL 只有 `?sharecode=KYSNKQPHS7`，覆盖发布后 URL 一字不变；CloudStudio Gateway 响应**没有 Cache-Control / ETag**，只有 Last-Modified → 浏览器按启发式缓存长期拿旧 `app.js` / `core/music.js`。手机浏览器（尤其微信内置）更顽固。
- 修复（只动 Web 构建链，业务代码零改动）：
  1. `scripts/build-web.mjs` 计算 `buildTag = pkg.version + '-' + sha256(app.js+style.css+core/music.js+core/changelog.js+seed-data.js)[:8]`，给三处 URL 注入 `?v=<buildTag>&sharecode=...`（HTML 属性里写 `&amp;`）；`version.json` 加 `build` 字段；`<html>` 写 `data-build`；head 注入 `Cache-Control/Pragma/Expires` 三个 no-cache meta。
  2. 新增 `src/web/versionCheck.js`（外链，CSP script-src 'self' 允许）：拉 no-store 的 `version.json` 比对 buildTag，不一致就带 `_v=<latest>` 参数 `location.replace` 一次，`sessionStorage` 按版本去重防死循环；旧版 version.json 无 build 字段时按 `version + '-'` 前缀兼容。构建脚本里把它加进 web/ 复制列表、脚本列表末尾、`SKIP_IN_CHECK`（vm bundle check 跑不了浏览器 API）。
  3. `test/web-version-check.test.js` 5 条断言（一致不刷新 / 不一致重载 / 去重不循环 / 旧版兼容 / 探测失败不刷新），挂进 `npm test`。
- 产物 buildTag = `1.38.0-ffc453b0`；线上 HTML、version.json 都是这个值，手机模拟 `autoReloaded=false`（无循环）、150 卡、零报错。
- **给用户的立即生效链接**：`https://linyu-translator.app.workbuddy.host/?sharecode=KYSNKQPHS7&v=1380`（入口 URL 变了必然绕过 HTML 缓存）。老分享链接的用户第一次仍需手动换链接/清缓存；此后每次覆盖发布会由 versionCheck 自动重载。
- 顺带确认 `release/linyu-translator-1.38.0-debug.apk` 内 `assets/public/core/music.js` 也是 150 条，安卓 App 不存在这个问题（本地 assets）。
