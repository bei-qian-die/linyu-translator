## Web 端白屏事故：TDZ（15:00~15:25）

部署后她报「网页端加载不出来」，整页空白只剩云按钮。

**根因**：上一版把 `DEFAULT_PROXY_URL` / `proxyUrl` 插到了 `nonDesktop` 定义**之前**：

```js
const proxyUrl = ref(nonDesktop ? DEFAULT_PROXY_URL : '');   // ← 这里
const nonDesktop = typeof window.api.isCapacitor === 'boolean';
```

`const` 的暂时性死区让 setup 一进第 47 行就抛
`ReferenceError: Cannot access 'nonDesktop' before initialization`，
Vue 捕获后渲染成 `<!---->`（7 字符），整页白屏，连 `.topbar` 都没有。
修法：把 DEFAULT_PROXY_URL + proxyUrl 整块挪到 `browserWeb` 之后。

### 定位过程（方法可复用）

## 外部访客免 Key 用润色（15:46~16:20）

需求：网页端**外部用户**（不下载 App、不填 API Key）也能用 AI 润色。

### 现状核查：通道早就通，但外部访客走不到

Node 侧实测：全新会话（session=null）调云服务 LLM **成功**，2.0s：
`他喜欢她。/ 塔喜翻塔厚。` → `塔喜翻塔惹，厚可爱捏♥`。
即「免 Key 内置通道」本身对匿名用户是放开的，问题全在前端默认值。

### 三个断点（都修了）

| # | 问题 | 现象 |
|---|---|---|
| 1 | **`nonDesktop` 永远判成 false** | 见下方「最大发现」 |
| 2 | `makeProxyPolish` 里 `readPolishPref('polishEngine','')` 缺省空串 | 没进过设置页 → 不走 cloud → 走代理 → 没地址 → 返回草稿，表现「勾了没反应」 |
| 3 | `polishOn` 默认 false | 外部访客不会主动去工具栏找开关 |

### 最大发现：`nonDesktop` 从上线起就是错的

Web 端在 db 初始化完成前，`window.api` 是 `webEntry.js` 挂的**占位 Proxy**，
它的 `isCapacitor` 是**函数**（`function(){return false}`）而不是布尔：

```js
const nonDesktop = typeof window.api.isCapacitor === 'boolean';  // → false（错）
```

于是浏览器里整站被当成桌面环境：设置页冒出「本机 Ollama」、`polishEngine` 默认 `ollama`、
`browserWeb` 为 false、润色默认关。**这就是之前她截图里「手机/网页也显示本机 Ollama」的真正原因**
（当时误判为旧包）。三种形态都要认：

```js
const __api = window.api || {};
const nonDesktop = __api.__isStub === true
  || typeof __api.isCapacitor === 'boolean'
  || typeof __api.isCapacitor === 'function';
```
Electron preload 两个字段都没有 → 仍是桌面，行为不变。

### 改动

- `src/renderer/app.js`
  · `nonDesktop` 三种形态判定（见上），并把它提到 `polishOn` 之前声明
  · `const polishOn = ref(nonDesktop)` —— 外部访客默认开，不依赖 onMounted 赋值
  · onMounted 里 `polishOn.value = parsePref(prefs['polishEnabled'], nonDesktop) === true`（尊重手动关过的人）
- `src/mobile/api.js`
  · `makeProxyPolish`：未设置引擎时默认 `cloud`；cloud 失败**抛出**（让 service 写 error，按钮能显示原因）
  · 结果缓存 `linyu.polish.cache.v1`（localStorage，LRU 300 条，key=原文+\0+草稿）：同句二次 0~3ms，省额度
  · 模型目录一次会话只拉一次（原来每次润色都 `models.list()`）
  · `cloudErrorText()`：把 429/402/401/超时翻成中文提示（额度用完会明说）
  · `withTimeout(...,15000)`：流式无超时，卡住时会一直转圈
- 新增 `scripts/verify-external.cjs`：临时 partition 模拟**全新访客**，断言默认勾选 + 匿名调通 + 缓存命中 + 换句不复用

## 润色默认切到智谱 glm-4-flash（免费），Key 只留服务端（20:22~21:10）

需求：网页外部访客默认调 glm-4-flash（免费），不下载、不填 Key。

### 三条硬事实（决定了架构）

1. **智谱不返回任何 CORS 头**（实测 OPTIONS 200，ACAO 命中 0）→ 浏览器直连不可能，
   除非把 Key 放前端（等于公开）→ 必须服务端中转。
2. **平台一个工作区只有一个已发布应用槽位**：把 polish-proxy 用 `language: node` 部署后，
   原静态站被顶掉（`/` 变 404、`/polish` 变「链接不完整」）。已立即重新部署 www-web 恢复。
3. **平台访问网关要求每个请求都带 sharecode**，`/polish`、`/health` 也不例外，
   不带就返回「链接不完整」的 HTML。

### 最终架构：linyu-server 一体部署

一个 Node 服务同时托管静态站 + `POST /polish`（同源，无跨域）：

```
linyu-server/
  index.js      # 静态托管（public/）+ /polish（调 glm-4-flash）
  prompt.json   # 提示词，构建时从 cloudfunctions/polish 导出（单一来源）
  .env          # ZHIPU_API_KEY（gitignore，不入库）
  public/       # ← www-web 构建产物，npm run server:prepare 同步（gitignore）
```

- 发布流程变成：`npm run web:build && npm run server:prepare` → deploy `linyu-server`（language=node）
- 限流：单 IP 30 次/分、400 次/天（保护免费额度）
- 前端：默认引擎 `proxy`，地址同源 `/polish`（相对路径），自动拼当前页 sharecode；
  代理失败自动回落内置通道并记住（`_proxyDead`），不会每句白等一轮

### 踩到的坑

- **服务层默认引擎还是 `'cloud'`**，与 UI 的 `'proxy'` 不一致 → `/polish` 一次都没被调用过
  （`/health` 的 `calls` 死活不涨）。判断「到底走了哪条路」用 calls 计数最可靠。
- 云函数 `config.json` 的 `timeout` / `envVariables` **不被 CLI 部署接受**
  （部署后 info 仍 timeout=3），云函数路线必须控制台手配，故放弃。
- 部署 Node 服务前一定确认 public/ 已同步，否则线上是 404/白屏。

### 质量修补（glm-4-flash 比大模型弱）

- 提示词加两条：「塔」不许换成小仙女/集美；不许新增草稿没有的人称词
- 服务端 `fixPronouns`：输出冒出他/她就换回塔。**不能加「输出里没有塔」这个前提**——
  模型常只把第二个塔写成她，第一个还在，条件不成立就漏修（「塔喜翻她厚」）
- 客户端护栏加 `LINYU_MARKERS`（神马/酱紫/靴靴/捏/厚礼蟹…）+ 命中即放行，
  否则「这是啥情况」→「这神马情况捏」因草稿特有字保留率归零被误杀

### 线上实测

```

polish: 今日天气珍好。→ 今日天气珍好惹♥（1070ms）
```

### 遗留

- **Key 已在对话里出现过**，建议她去智谱后台重置一个，改 `linyu-server/.env` 再发一次
- run2（同句第二次）仍 4332ms，缓存没命中，原因未查明（pcacheSet/pcacheGet key 怀疑不一致）
- 安卓 App 内默认仍是 zhipu 直连，本轮未动

### 参考片风格（查证结果）
- `api.bilibili.com/x/web-interface/view?bvid=` 可取标题/封面；`/x/player/pagelist` 取分辨率
- 该片是 **1920×1080 横屏讲解**，5:19；首帧=近黑底 + 极细无衬线 + 居中一行小字（`42.3平`）
- 封面是橙+米黄的手绘图解。**取的是视频本体那套极简深色语言，不是封面**

### 配色/版式（promo/mp/mp2.html）
- `#0E0E0D` 底 / `#F4F1EB` 文字 / `#FF6B35` 唯一强调色；左上章节编号 01—05；顶部 3px 进度线
- 手机 620×1339（截图 546×1179 → 1.135 倍，几乎无损），缓推 4.5% 由虚拟时间算
- 21 个节拍，**节拍切点绑字幕边界**（BEATS 存的是「第几条字幕开始」），改文案不会错位

### 配音链路（promo/mp/）
- `tts.py`：edge-tts `zh-CN-XiaoxiaoNeural`，rate +6%，11 句 → mp3 + 48k 单声道 wav，**用 wave 帧数测时长**（ffmpeg-static 没有 ffprobe）
- `spec.py`：LEAD 700 / GAP 400 / TAIL 1600，句内按字数分配字幕时间 → `timeline.js` + `字幕.srt`
- `build_audio.py`：adelay 铺轨 → 峰值归一 → 程序合成 Am–F–C–G 四和弦垫乐（每 4s 一个，afade 0.9s）→ amix → 收尾统一拉到 -1.2dB
- 成片 69.4s / 2083 帧 / AAC 192k 立体声

### 踩的坑
1. **`npm i X --no-save` 会删掉之前 --no-save 装的包**（再次验证）：ffmpeg-static + miniprogram-automator 必须一起装
2. **`ffmpeg-static` 里没有 ffprobe.exe**，只能 `ffmpeg -i` 或转 wav 读帧数
3. **display:none 子树里的 img 解码是懒的**：逐帧渲染时会出现「手机卡片空白整整 3 秒」。修法=启动时 `[...document.images].map(im=>im.decode())` 全解完再暴露 `__renderAt`（用 Promise.race 加 9s 兜底）
4. 渲染脚本依赖 `__tl().SUBS`（平铺 {start,end,text}）导 SRT，页面没给就会 `Cannot read properties of undefined (reading 'map')`
5. `console.log(str.join('\n")'))` 这类手误会让 node --check 直接挂，改完必须跑一次语法检查
6. heredoc 里写 python 补丁时反斜杠会被吃（`\\s` → `//s`），正则改成字符串切分更稳

### 校验（promo/mp/verify.cjs）
闭环验成片而不是只看 DOM：从页面读 `__beats()` + 每节拍的 img，再对成片按 0.25s 采样**手机区域 (crop 620:1339:230:238) 的 YAVG**，亮帧占比 <90% 判为空镜。9 段手机镜全过、无黑帧。
另有 `assert2.cjs`：26 条字幕（文字/单行/不贴边）+ 21 个节拍（单幕单节拍/元素可见/图片已加载）。

### 配音口径（要跟用户说清）
剪映「知性女声」没有对外接口，只能界面手点；11 句点 11 次不可复现。用了微软神经网络女声替代，并把逐句 wav 留在 `promo/mp/voice/` 方便替换。**「阴乐」给 TTS 的文本换成「音乐」**，否则读成 yīn lè，同音梗就废了。
