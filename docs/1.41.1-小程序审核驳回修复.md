# 1.41.1 小程序审核驳回修复说明

> 驳回结论：存在无法加载 / 页面白屏问题，违反《微信小程序平台运营规范常见拒绝情形》3.3
> 详情描述：「小程序页面存在：【复制】无法加载完整数据内容、页面白屏、页面报错等情形，暂无法体验小程序核心功能」
> 审核附带的截图里，小程序停在「音乐」页，浮层写着「复制失败，请长按选择文本」。
> 也就是说：**复制这条链路在审核机上必然失败**，其它措辞是同一处失败的连带描述。

## 一、根因：隐私授权写法不合规，剪贴板被永久拒绝

`miniprogram/app.js` 在 `onLaunch` 里注册了自绘隐私弹窗：

```js
wx.onNeedPrivacyAuthorization((resolve) => {
  wx.showModal({
    ...
    success: (res) => resolve({ event: res.confirm ? 'agree' : 'disagree' }),
  });
});
```

微信官方文档（小程序隐私协议开发指南 · 被动监听隐私接口需要用户授权事件）要求：
自定义弹窗必须在 `<button open-type="agreePrivacyAuthorization">` 的回调里
`resolve({ buttonId: 'agree-btn', event: 'agree' })`。**缺 `buttonId` 时授权不会被记录**。

更关键的是官方弹窗兜底逻辑：

> 当开发者调用隐私相关接口时，微信会判断此次调用是否需要触发 `onNeedPrivacyAuthorization` 事件，
> 若触发后**开发者未进行响应**，微信将主动弹出官方弹窗。

我们既「响应了」，又没有给出合法 `buttonId` —— 微信既没记录同意，也不再兜底弹窗，
`wx.setClipboardData` 于是每次都失败（`errno 112 / 103 / 104`），页面走到
`toast('复制失败，请长按选择文本')`，而页面上并没有任何可选中的文本，用户和审核员都无路可走。

`wx.setClipboardData` 属于隐私接口，另外两种情况同样会失败：

| errno / errMsg | 含义 | 谁能修 |
| --- | --- | --- |
| `112 api scope is not declared` | 后台《用户隐私保护指引》没勾「剪贴板」 | **只能人工在 mp 后台勾** |
| `103 / 104` | 用户在官方隐私弹窗点了拒绝 | 代码侧重新走一次授权 |
| `appid privacy api banned` | 提审时勾了「未采集隐私」，平台回收接口权限 | 重新提审时不勾 |
| 其它 | 基础库过低（< 2.32.3 不拦截）或环境异常 | 代码侧降级 |

## 二、代码改动

| 文件 | 改动 |
| --- | --- |
| `miniprogram/app.js` | 删除不合规的 `onNeedPrivacyAuthorization` 注册，改由微信官方隐私弹窗兜底；保留说明注释 |
| `miniprogram/utils/ui.js` | `copy()` 改为返回 `Promise<boolean>`：先 `wx.requirePrivacyAuthorize`（≥2.32.3），再写剪贴板；失败按 `112 / 103 / 104 / banned` 归类并写进实时日志 |
| `miniprogram/utils/copySheet.js` | 新增 `attachCopySheet(page)`：注入 `copyText / closeCopySheet / retryCopy`，复制失败时弹「手动复制」面板 |
| `miniprogram/templates/copy-sheet.wxml` | 新增面板模板：`<text user-select>` 让文字可长按全选，带「关闭 / 再试一次」 |
| `miniprogram/app.wxss` | 面板样式（遮罩 + 底部卡片 + 次按钮），跟随三套主题变量 |
| 5 个页面（翻译 / 历史 / 音乐 / 人物 / 词库浏览） | 全部接 `attachCopySheet` 与 `<template is="copy-sheet" />`，所有 `copy(...)` 调用改为 `this.copyText(...)` |
| `pkg-hero/pages/browse` | 数据加载失败从「静默空列表」改为「内容加载失败 · 重新加载」提示条（原样最容易被判成「无法加载完整数据」） |
| `pkg-hero/pages/hero` | `require` 数据抛错不再中断 `onLoad`（此前页面只剩空壳），改为「人物数据加载失败 · 重新加载」 |
| `test/weapp.test.js` | 同步新契约：不再断言 `onNeedPrivacyAuthorization` 已注册；新增「112 / 用户拒绝 → 弹手动复制面板」用例；复制用例改为 `await` |

改完之后，无论后台有没有声明「剪贴板」，「复制」这个动作都能完成：

1. 有权限 → 直接写剪贴板，`已复制♥`
2. 首次 → 微信官方隐私弹窗，同意后写入
3. 拒绝 / 未声明 / 被回收 → 弹「手动复制」面板，长按全选复制，还能「再试一次」

## 三、必须人工做的一步（代码替代不了）

1. 打开 <https://mp.weixin.qq.com> → 设置 → 服务内容声明 → **用户隐私保护指引** → 更新
2. 增加信息类型 → 勾选 **「剪贴板」**
3. 用途填写（可直接粘贴）：
   > 用于把音源链接、译文、词条与名言内容写入本机剪贴板，便于用户粘贴到浏览器或其他 App 打开；剪贴板内容不会上传服务器，也不读取与功能无关的内容。
4. 保存并生成协议，**5 分钟后生效**
5. 重新提审时，**不要**勾选「未采集隐私」（勾了会得到 `appid privacy api banned`）

> 只做代码修复、不补这一步的话，功能仍然可用（会走手动复制面板），但审核员点「复制」看到的
> 是浮层而不是系统「内容已复制」提示，体验打折，也更容易被再次质疑。

## 四、提审「补充说明」模板

> 本次已修复上版驳回的「复制失败」问题。原因是我方自定义隐私弹窗缺少
> `open-type="agreePrivacyAuthorization"` 的 buttonId，导致剪贴板接口被持续拒绝；
> 现已改为使用微信官方隐私弹窗，并在剪贴板不可用时提供「手动复制」面板（文字可长按选中）。
> 核心功能体验路径：
> 1. 首页输入任意中文 → 点「翻译」查看淋语结果 → 点「复制」
> 2. 底部「音乐」→ 任一音源 → 「复制音源链接」/「复制搜索词」
> 3. 底部「词库」→ 搜索「野花香」→ 点词条复制；「人物」→ 点任人物进详情 → 复制链接 / 词条 / 名言
> 4. 「历史」→ 长按记录复制译文，或用「导出」批量复制
>
> 《用户隐私保护指引》已声明「剪贴板」，仅用于上述复制功能，不读取无关内容。

## 六、为什么没有重新打包 PC / 安卓

本次只有小程序端（`miniprogram/`）行为变化，Electron 与 Capacitor 产物不引用这些文件，
重新出 exe / apk 只会改版本号，不会改行为。版本号已升到 `1.41.1`，下次出包自然带上。
